# PIU v1 — Execution Plan

> This document is a prescriptive, copy-friendly guide for implementing PIU v1. It assumes the implementing model has read `docs/v1.md` for context. Every section below is meant to remove ambiguity: file paths are exact, snippets are canonical, and acceptance criteria are explicit. Execute the phases **in order**.

---

## 0. How to use this document

* Always cross-check decisions with `docs/v1.md`. If anything conflicts, `docs/v1.md` is the source of truth for *what* and this plan is the source of truth for *how*.
* Work phase-by-phase. Do not start phase N+1 until phase N's acceptance criteria are met.
* Prefer the libraries and versions listed in section 1. Do not introduce new runtime dependencies without need.
* Keep code in TypeScript (backend, frontend) and Go (monitor). No JavaScript files in `backend/src`.
* All paths in this document are relative to the repository root unless stated otherwise.

## 3. SQL schema (final)

`backend/src/database/migrations/001_init.sql`:

```sql
PRAGMA journal_mode = WAL;
PRAGMA foreign_keys = ON;

CREATE TABLE IF NOT EXISTS inputs (
  id           INTEGER PRIMARY KEY AUTOINCREMENT,
  name         TEXT    NOT NULL,
  type         TEXT    NOT NULL CHECK (type IN ('directory')),
  source_path  TEXT    NOT NULL,
  extensions   TEXT    NOT NULL DEFAULT '["png","jpg","jpeg","gif","webp"]',
  is_active    INTEGER NOT NULL DEFAULT 1 CHECK (is_active IN (0,1)),
  created_at   TEXT    NOT NULL DEFAULT (datetime('now')),
  updated_at   TEXT    NOT NULL DEFAULT (datetime('now'))
);

CREATE UNIQUE INDEX IF NOT EXISTS idx_inputs_source_path ON inputs(source_path);

CREATE TABLE IF NOT EXISTS outputs (
  id                  INTEGER PRIMARY KEY AUTOINCREMENT,
  name                TEXT    NOT NULL,
  input_type          TEXT    NOT NULL CHECK (input_type IN ('directory')),
  type                TEXT    NOT NULL CHECK (type IN ('discord_bot','discord_webhook')),
  file_patterns       TEXT    NOT NULL DEFAULT '[]',
  is_fallback         INTEGER NOT NULL DEFAULT 0 CHECK (is_fallback IN (0,1)),
  destination_config  TEXT    NOT NULL,
  is_active           INTEGER NOT NULL DEFAULT 1 CHECK (is_active IN (0,1)),
  created_at          TEXT    NOT NULL DEFAULT (datetime('now')),
  updated_at          TEXT    NOT NULL DEFAULT (datetime('now'))
);

-- Enforce at-most-one fallback per input_type.
CREATE UNIQUE INDEX IF NOT EXISTS idx_outputs_one_fallback_per_input_type
  ON outputs(input_type) WHERE is_fallback = 1;
```

**Migration runner** (`backend/src/database/migrate.ts`): read every `.sql` file under `migrations/` in lexical order, execute as a single transaction, and record applied migrations in a `_migrations` table:

```sql
CREATE TABLE IF NOT EXISTS _migrations (
  name TEXT PRIMARY KEY,
  applied_at TEXT NOT NULL DEFAULT (datetime('now'))
);
```

Skip migrations whose `name` already exists in `_migrations`.

`transaction.json` schema:

type TransactionMeta = {
  txn_id: string;            // uuid v4
  original_name: string;     // basename of the source file

  input_id: number;
  input_type: 'directory';
  discovered_at: string;     // ISO 8601 with local TZ offset

`deliveries/<output_id>.json` schema:

```ts
type DeliveryState = {
  output_id: number;
  output_type: 'discord_bot' | 'discord_webhook';
  status: 'pending' | 'success' | 'error' | 'dlq';

  global_reprocesses: number;
  last_error: string | null;
  last_attempt_at: string | null; // ISO 8601
};
```

**Atomic writes for JSON files:** always write to `<file>.tmp` then `fs.renameSync(<file>.tmp, <file>)`. Never edit JSON in place.

## 5. Routing algorithm (pseudocode)

```ts
function route(filePath: string, input: Input): number[] {
  const basenameLower = path.basename(filePath).toLowerCase();
  const ext = path.extname(filePath).slice(1).toLowerCase();

  // Extension whitelist (silently ignore on miss)
  if (!input.extensions.includes(ext)) return [];

  const activeRules = outputsRepo.findActive({
    input_type: input.type,
    is_fallback: false,
  });

  const matched: number[] = [];
  for (const rule of activeRules) {
    const patterns: string[] = JSON.parse(rule.file_patterns);
    for (const p of patterns) {
      if (basenameLower.includes(p.toLowerCase())) {
        matched.push(rule.id);
        break; // a rule only needs one matching pattern to be selected
      }
    }
  }

  if (matched.length > 0) return matched;

  const fallback = outputsRepo.findFallback(input.type);
  return fallback ? [fallback.id] : [];
}
```

If `route()` returns an empty list, the transaction is created directly in `dlq/` with a `transaction.json` and a synthetic `deliveries/no_route.json` carrying `last_error: "No matching rule and no fallback configured"`. Emit a `delivery_dlq` event so the UI can surface it.

## 6. Delivery state machine (pseudocode)

```ts
async function attemptDelivery(txnDir: string, deliveryFile: string) {
  const delivery = readDelivery(deliveryFile);
  if (delivery.status !== 'pending') return;

  const output = outputsRepo.getById(delivery.output_id);
  const imagePath = findImage(txnDir);

  try {
    await adapters[output.type].upload(imagePath, JSON.parse(output.destination_config));
    delivery.status = 'success';
    delivery.last_error = null;
    delivery.last_attempt_at = nowIso();
    writeDelivery(deliveryFile, delivery);
    emit('delivery_success', { txn_id, output_id: delivery.output_id });
  } catch (err) {
    if (isRateLimit(err)) {
      const retryAfterMs = parseRetryAfter(err);
      setTimeout(() => attemptDelivery(txnDir, deliveryFile), retryAfterMs);
      return;
    }

    delivery.immediate_attempts += 1;
    delivery.last_error = serializeError(err);
    delivery.last_attempt_at = nowIso();

    if (delivery.immediate_attempts < 3) {
      writeDelivery(deliveryFile, delivery);
      return attemptDelivery(txnDir, deliveryFile); // retry immediately
    }

    delivery.immediate_attempts = 0;
    delivery.global_reprocesses += 1;

    if (delivery.global_reprocesses > 3) {
      delivery.status = 'dlq';
      writeDelivery(deliveryFile, delivery);
      emit('delivery_dlq', { txn_id, output_id: delivery.output_id });
    } else {
      delivery.status = 'error';
      writeDelivery(deliveryFile, delivery);
      emit('delivery_error', { txn_id, output_id: delivery.output_id });
      moveTransactionTo('error', txnDir);
      setTimeout(() => requeueErrorDelivery(deliveryFile), 60_000);
    }
  } finally {
    finalizeIfTerminal(txnDir);
  }
}

function requeueErrorDelivery(deliveryFile: string) {
  const d = readDelivery(deliveryFile);
  if (d.status !== 'error') return;
  d.status = 'pending';
  writeDelivery(deliveryFile, d);
  moveTransactionTo('pending', dirOf(deliveryFile));
  attemptDelivery(...);
}

function finalizeIfTerminal(txnDir: string) {
  const states = listDeliveries(txnDir).map(d => d.status);
  if (states.every(s => s === 'success')) {
    moveTransactionTo('confirmed', txnDir);
    emit('transaction_completed', { txn_id, dlq: false });
  } else if (states.every(s => s === 'success' || s === 'dlq')) {
    moveTransactionTo('dlq', txnDir);
    emit('transaction_completed', { txn_id, dlq: true });
  }
}
```

**Concurrency rule:** all deliveries inside the same transaction may run in parallel. Use `Promise.allSettled` per transaction. Across transactions, no global limit in v1 (single-user, low volume).

## 7. Go stdin/stdout protocol (final)

Commands sent by Node to Go via `stdin` (one per line, terminated by `\n`):

| Command                          | Effect                                                           |
| -------------------------------- | ---------------------------------------------------------------- |
| `WATCH:<absolute_path>`          | Walk and register every existing subdir under root.              |
| `UNWATCH:<absolute_path>`        | Remove root + all sub-watchers and prune internal state.         |
| `PING`                           | Reply `PONG` on `stdout` (optional health probe).                |

Lines from Go on `stdout`:

* `<absolute_path>` — one per stable file detected (after the 600 ms size-stability window).
* `PONG` — reply to `PING`.

Lines from Go on `stderr`:

* Free-form diagnostic text. Node forwards them to its pino logger as `level=info` with `source=go_monitor`.

**Path normalization:** Node sends paths in OS-native form (Windows uses `\`). Go does not mutate paths; the path emitted on `stdout` is the exact form `fsnotify` reported (after `filepath.Abs`).

**Initial scan:** Go does **not** emit existing files on `WATCH`. Only files created or modified after the watch attaches are reported.

## 8. REST + SSE API contract

All endpoints are JSON, bound to `127.0.0.1:3737`, prefix `/api`.

### Inputs

* `GET /api/inputs` → `Input[]`
* `POST /api/inputs` body `{ name, source_path, extensions?, is_active? }` → `Input` (201).
* `PATCH /api/inputs/:id` body partial → `Input`.
* `DELETE /api/inputs/:id` → 204.

Side effects on POST/PATCH/DELETE: emit `WATCH:`/`UNWATCH:` to the Go process as needed.

### Outputs

* `GET /api/outputs` → `Output[]`
* `POST /api/outputs` body `{ name, input_type, type, file_patterns, is_fallback, destination_config, is_active? }` → `Output` (201).
* `PATCH /api/outputs/:id` body partial → `Output`.
* `DELETE /api/outputs/:id` → 204.

Validation rules enforced server-side:

* `destination_config` shape matches `type` (`discord_bot` requires `bot_token` + `channel_id`; `discord_webhook` requires `webhook_url`).
* At most one fallback per `input_type` (enforced by the partial unique index in SQL + a friendly 409 from the API).

### Dashboard

* `GET /api/dashboard/stats` → `{ synced: number; pending: number; error: number; dlq: number; goRunning: boolean }`. Counts are computed by walking the storage tree (cache the count with a 1-second TTL to avoid hammering disk on dashboard polling).

### DLQ

* `GET /api/dlq` → list of DLQ transactions:
  ```ts
  type DlqEntry = {
    txn_id: string;
    bucket: string;          // YYYY-MM-DD
    transaction: TransactionMeta;
    deliveries: DeliveryState[];
  };
  ```
* `POST /api/dlq/:txn_id/retry` → resets DLQ deliveries to `pending` and moves the folder back to `pending/`. 204.
* `DELETE /api/dlq/:txn_id` → recursively removes the folder. 204.

### Events (SSE)

* `GET /api/events` → `Content-Type: text/event-stream`.

Emit one named SSE event per occurrence. Event names and payloads:

| Event                  | Payload                                                                 |
| ---------------------- | ----------------------------------------------------------------------- |
| `file_received`        | `{ txn_id, original_name, input_id }`                                   |
| `delivery_success`     | `{ txn_id, output_id }`                                                 |
| `delivery_error`       | `{ txn_id, output_id, last_error }`                                     |
| `delivery_dlq`         | `{ txn_id, output_id, last_error }`                                     |
| `transaction_completed`| `{ txn_id, dlq: boolean }`                                              |
| `heartbeat`            | `{ at: string }` — emitted every 15 s to keep the connection alive.     |

Server-side SSE implementation notes: write `: keep-alive\n\n` every 15 s and `event: <name>\ndata: <json>\n\n` for each event. Close the connection cleanly on client disconnect.

### Phase 9.2 — Go monitor

Write `go_monitor/main.go` with these responsibilities:

1. Create one global `*fsnotify.Watcher`.
2. Maintain `roots map[string]*rootState` guarded by `sync.Mutex`. `rootState` holds the set of subdirs registered under that root and a `context.CancelFunc`.
3. Goroutine 1: read `os.Stdin` line by line with `bufio.Scanner`.
   * `WATCH:<path>` → call `addRoot(path)`. `addRoot` does `filepath.Walk(path)`, adds every dir to the watcher, records them in `rootState.subdirs`.
   * `UNWATCH:<path>` → call `removeRoot(path)`. Iterate `rootState.subdirs`, call `watcher.Remove`, cancel the context, delete from `roots`.
   * `PING` → `fmt.Println("PONG")`.
4. Goroutine 2: consume `watcher.Events`.
   * On `CREATE` of a directory under any known root: `watcher.Add` that dir and walk it for nested children.
   * On `CREATE` or `WRITE` of a file: start (or refresh) a stability tracker for that path.
5. Stability tracker:
   * `map[string]*stabilityState{ size int64, lastChange time.Time }` with a mutex.
   * On every event for the path, update `size` to current `os.Stat` size and `lastChange = now`.
   * A separate ticker goroutine (every 200 ms) iterates the map: if `now - lastChange >= 600 ms` AND a re-stat returns the same size → emit the absolute path on `stdout` and delete from the map.
6. All errors go to `os.Stderr` with `log.Println`. Never to `stdout`.
7. Trap SIGINT/SIGTERM to close the watcher and exit cleanly.

**Acceptance:** Manually run `./backend/bin/piu-monitor`, type `WATCH:C:/tmp/piu-test` + Enter, drop an `.png` file in `C:/tmp/piu-test`, and observe the absolute path printed on stdout after ~600 ms. Drop a directory containing a file and confirm the nested file is reported too.

3. `backend/src/util/dates.ts`: `localBucket(date = new Date()): string` returning `YYYY-MM-DD` in local time.

   ```ts
   export interface DiscordAdapter {
     upload(filePath: string, config: unknown): Promise<void>;
   }
   ```

   The adapter throws a structured error `{ status: number, body: string, retryAfterMs?: number }` on failure.

10. `backend/src/discord/botAdapter.ts`:
    * Validate config shape `{ bot_token, channel_id }`.
    * `POST https://discord.com/api/v10/channels/<channel_id>/messages` with `Authorization: Bot <bot_token>`, body `FormData` containing `files[0]` = the file stream.
    * On 429, parse `Retry-After` header (seconds) → throw with `retryAfterMs`.

11. `backend/src/discord/webhookAdapter.ts`:
    * Validate config shape `{ webhook_url }`.
    * `POST <webhook_url>` with the same multipart body, no auth header.
    * Same 429 handling.

12. `backend/src/pipeline/dispatcher.ts`: for a given `txnDir`, list pending deliveries and run `attemptDelivery` for each in parallel (`Promise.allSettled`). Called by:
    * the file-detected callback (right after `createPendingTransaction`),
    * `recovery.ts` at boot,
    * the `setTimeout` after 1 minute in error state.

13. `backend/src/pipeline/stateMachine.ts`: contains `attemptDelivery`, `finalizeIfTerminal`, `moveTransactionTo`. Emits events via `eventBus`.

14. `backend/src/pipeline/recovery.ts`:
    * Walk `storage/transactions/image_upload/pending/**/transaction.json` → for each, dispatch.
    * Walk `storage/transactions/image_upload/error/**/transaction.json` → for each, schedule `setTimeout(..., 60_000)` to flip its `error` deliveries back to `pending`.

15. `backend/src/index.ts` order:
    1. Acquire lock.
    2. Configure logger.
    3. Run migrations.
    4. Run recovery.
    5. Start Express (section 9.4).
    6. Spawn Go process.
    7. Hydrate inputs.

**Acceptance:** `npm run dev:backend` boots without errors, Go child process is logged, dropping a PNG matching a configured rule sends it to Discord (verified against a real webhook). Killing Node and restarting resumes any in-flight `pending/` transaction.

### Phase 9.4 — REST + SSE

## 10. Conventions for the executor model

* **Indentation:** 2 spaces for TS/JSON, tabs for Go (gofmt default), 2 spaces for Angular templates.
* **No magic numbers:** constants like the 200 ms poll, 600 ms stability window, 60 s error timer, 3 immediate retries, 3 global reprocesses, and 1 s stats cache TTL must be defined in `backend/src/config.ts` and `go_monitor/main.go` as named constants.
* **Time:** always `new Date().toISOString()` for storage in JSON metadata; the local `YYYY-MM-DD` bucket comes only from `dates.ts`.
* **Error logging:** use `logger.error({ err, ctx })`. Never `console.error`.
* **File naming:** camelCase for TS files (e.g., `inputSync.ts`), kebab-case for Angular component files, snake_case for SQL migration files prefixed with a zero-padded order (`001_init.sql`).
* **No comments narrating the code.** Comments only for non-obvious rationale.
* **No new top-level dependencies** beyond the table in section 1 unless absolutely required. If a new dep is needed, justify it in the README.
* **Tests:** v1 does not require an automated test suite. Manual smoke test (section 9.6) is the acceptance bar. Any unit tests added should live next to the file as `*.test.ts` and run with `node --test`.
* **Concurrency:** use `Promise.allSettled`, not `Promise.all`. Never let one delivery error crash another.
* **Process safety:** never `process.exit` from inside request handlers or pipeline code. Only `index.ts` may exit, and only during boot failures.
* **Cross-platform:** the code must run on Windows, Linux, and macOS. Always use `path.join`, never string concatenation for paths.
